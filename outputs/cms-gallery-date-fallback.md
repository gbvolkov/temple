# Дата фотоальбома при отсутствии года в URL

Исправлена причина CMS-70: корректная сохранённая дата используется при отсутствии распознанного года в URL. Для примера `/20241/`, заголовка `06 октября` и `event_date=2024-10-06` дата принимается автоматически; `event_date_precision` для этого не требуется. При наличии года в URL действует ранее согласованный приоритет URL; противоречие дней остаётся причиной проверки. Импортная техническая заглушка `2000-01-01` без подтверждения сама по себе не считается распознанной датой. Сохранённую пользователем 01.01 другого года можно принять, а метка точности `year` сохраняет значение «только год».

Версия правил подготовки увеличена до 1.3.1, чтобы ранее сформированный preview нельзя было применить. Фото и статусы отдельно этим изменением не редактируются. Исходный тест сначала воспроизвёл дефект; затем исправление прошло полный контур и было применено на production.


Найден и сначала воспроизведён CMS-71: удаление `body_text` при неразрешённом конфликте дат скрывало исходные признаки, из-за чего повторная подготовка могла менять решение. Исправление сохраняет исходный текст для таких альбомов; при повторной подготовке конфликт не исчезает. Конкретный пример из исходной базы проверен дважды без дополнительных изменений. Полный контур после исправления пройден.
