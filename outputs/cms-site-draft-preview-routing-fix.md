# Исправление перехода к сайту с черновиками

24 ноября 2026 года. **Исправление развёрнуто на production и проверено в браузере через внешний домен CMS.** Причина обращения пользователя воспроизведена отдельным браузерным characterization-тестом до исправления.

## Причина

Production использует разные домены: публичный `temple.gbvolkoff.name:8443` и редакционный `cms.temple.gbvolkoff.name:8443`. В nginx редакционного домена точный путь `/` перенаправляется на `/cms.html` до обработки запроса приложением, причём параметр preview теряется. Прежняя относительная ссылка `/?preview=drafts` поэтому открывала CMS. Предыдущая приёмка проверяла приложение напрямую и анонимный публичный домен; такой положительный проход через редакционный reverse proxy она не покрывала.

## Исправление

- Вход в обычный сайт с рабочими версиями: `https://cms.temple.gbvolkoff.name:8443/preview?preview=drafts`.
- `/preview` использует тот же шаблон главной страницы и данные сайта, что `/`, под существующей проверкой сессии CMS. Публикации и состояния материалов не меняются.
- Все ссылки на главную и legacy hash-переходы в режиме черновиков ведут на `/preview?preview=drafts`. Сессия остаётся на своём домене; расширение cookie на публичный домен не требуется.
- Кнопка открывает сайт в текущей вкладке. Несохранённые правки защищены выбором сохранить / перейти без сохранения / остаться. Ссылка «В CMS» возвращает редактор, «Выйти из предпросмотра» — опубликованный сайт на публичном домене.
- Без preview параметра `/preview` перенаправляет на публичный сайт; без сессии запрос с параметром возвращает 401. Неизвестный или повторённый параметр отклоняется.
- Nginx и доступность административных API на публичном домене не меняются.
